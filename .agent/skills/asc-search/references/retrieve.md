# 检索工作流

打通「算子需求 → 意图分析 → 索引查询 → 分阶段候选文档」链路。检索入口是本 skill 的
`scripts/query.py`，本工作流只定义检索流程与输出规范，不新建索引数据、不改写索引。
推导规则见 [index_derivation_contract.md](index_derivation_contract.md)；建索引细节见 [index.md](index.md)。
命令均从仓库根目录执行。

## 步骤 0：索引前置保障

任何检索开始前先运行（用户显式指定架构/版本时透传参数，否则默认使用 3510 架构并自动检测本地 CANN 版本）：

```bash
python3 .agent/skills/asc-search/scripts/ensure_index.py --json [--arch A3] [--cann-version 9.2.0]
```

- ensure 按「CANN 版本 × 架构 × 层级」检测 committed 索引：筛选条件匹配且指纹新鲜 → 零动作；
  缺失、筛选条件不符或漂移 → 原地重建（本地 diff，不主动提交）。
- 成功后以输出 JSON 作为本次检索上下文：`cann_version/arch_label/categories` 共同定义
  **文档范围内**（换筛选条件 = 换索引实例，不要把当前检索范围之外的缺失误写为「仓库不支持」）；
  `actions` 含 `rebuilt` 时向用户说明一句。
- 失败（检测不到本地版本、构建校验不过）：如实报告错误并停止，不得绕过索引猜测文档，
  也不得把失败当成「仓库不支持」。

## 意图分析（先于任何查询）

从需求中抽取意图要素并映射到索引维度：

| 要素 | 示例 | 映射查询 |
| --- | --- | --- |
| 阶段/数据流向 | GM→UB 搬入、结果写回 | `--stage in[,out]` |
| 操作语义 | 拷贝、加法、矩阵乘累加、排序 | `--operation copy,add,matrix_multiply_accumulate,…` |
| API 分类 | 只看搬运类/寄存器计算类 | `--api-class vector_datamove,reg_compute,…` |
| 数据类型/精度 | half→fp8、int4、低精度 | `--convert <src> <dst[,dst2]>`（别名 f32/e4m3 可用）、`--dtype`、`--feature` |
| 行为约束 | 非对齐、填充、掩码、舍入 | `--kw`（title+description 子串） |
| 版本/产品 | 9.1.0 起可用、950 支持 | `--version '>=9.1.0'`、`--product 950,A3` |
| 具名 API 全貌 | asc_copy_gm2ub 家族 | `--api <name>`（主页+家族成员+分类页） |
| 参数/枚举/宏反查 | round_mode、ASC_CAST_RN | `--param`、`--enum` |
| 配套关系 | 掩码/填充/循环搬运配置 | `--deps-of <api> [--kind requires|configures] [--reverse]` |

**明确性判据**——同时满足才检索：

1. 至少 1 个可映射信号（上表任一）；
2. 无影响候选集的歧义：同一目标多解且无主次（如裸词「转换」无法区分 dtype 转换与
   位置搬运）。

**不明确 → 不检索，反问**：不执行任何查询（含 `--gap`）。同一检索需求累计最多反问 3 轮，
每次向用户发出一组澄清问题计为 1 轮；每轮最多 3 个问题，按信息量排序。每个问题给选项
（值域取自索引维度：stage 取 in/out/compute、operations 取词表值、架构取 3510/A3…），
并说明答案如何影响检索。用户回答后重新过判据，仍不明确且未达到上限时可继续反问。
达到 3 轮后仍不明确时停止反问，说明信息不足，列出已确认条件与待确认项，不猜测条件
或推荐接口。检索循环或索引重建不会重置同一需求的反问轮数。

**意图明确但信息不全 → 照常检索**：dtype、对齐等缺项不影响「要找什么」的判断时直接
检索，缺项列入输出「待确认」；完整多阶段需求（搬入+计算+搬出）是明确意图，拆解为
多信号查询，不是歧义。

## 检索循环（可多轮）

1. **初查**：主信号 → 维度映射查询；结果过宽时加维度收窄（各维度 AND、逗号值 OR）。
2. **空结果降级链**：精确 `--operation` → `--kw` 同义词（中英文、缩写都试）→
   `--api-class` + `--kw` → `--gap <关键词>` 确认是否范围外。仍无则如实说明。
   具名 API/路径未命中、维度值不在索引中时脚本一律返回空（不报错），按本链继续降级。
3. **配套展开**：候选 API 的 `--deps-of`（含 `--reverse`）展开依赖与配置；`--enum`/`--param`
   反查外部枚举与宏；家族变体保留（「对齐搬运」需求下 `asc_copy_*` 与 `asc_copy_*_align`
   同时保留；条件依赖注意 `condition` 提示）。
4. **按需核对**：只读候选文档中支撑推荐所需的章节（功能说明/约束说明），区分
   「已确认适用 / 条件待确认 / 范围内未覆盖」；禁止全量精读。
5. **收敛**：已明确的意图要素全部有候选或确认范围外，且依赖闭合 → 按输出格式作答。
   用户追问时按同一循环定向再查（不重跑 ensure，除非用户改了架构/版本筛选条件）。

## 输出把关（Agent 责任）

`query.py` 只负责给候选与命中原因，不代替判断。输出前由你逐条复核：

- **相关性**：候选是否真的满足用户意图；不相关的不展示，宁可少而准，不堆列表。
- **适用性**：架构/版本筛选条件、`condition` 待确认、deprecated 替代关系要显式说明。
- **完整性**：返回多个候选且无法确认已覆盖当前需求的全部适用接口时，在候选列表后原样注明
  “候选仅供参考，不代表全量接口。”
  索引查询成功或候选均已核对，不等于候选集完整。
- **空结果**：脚本空结果≠仓库不支持；先走降级链，再 `--gap`，最后才说范围外。
- 候选过宽时先收窄再输出；不得把脚本原始输出直接转发给用户。

## 输出格式（不落盘）

```text
## 候选
- 路径: docs/zh/api/SIMD-API/c_api/xxx/yyy.md 或 include/... | API: asc_yyy | 用途: 一句话
```

未检索到候选时直接说明结果，不单设未覆盖章节。必要时保留待确认事项。用户主动询问后再展开接口细节或算子实现。

## 检索策略要点

- **同步需求**：`--operation synchronization` 覆盖核间/流水线同步（含废弃同步接口）；
  语义细节读 sync 概念页；UB 地址重叠约束经 `--deps-of <搬运接口> --kind requires` 展开。
- **枚举/宏适配**：外部枚举与宏经 `--enum`/`--param` 反查（含 defs 头文件目录与使用方）。
- **缺口判断**：首选 `--gap`；未命中时如实说明「范围内未覆盖」并给出范围外线索
  （c_api 之外：adv_api/tensor_api/basic_api/SIMT/AI-CPU 等其他 API 层级）。
- 索引缺失或失效时说明限制并回流索引构建工作流（[index.md](index.md)），
  不能把范围内未检索到写成仓库不支持。
